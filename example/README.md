# 示例：一个能直接跑通的模块

不必先读懂 14 条规则。clone 下来，跑 30 秒，看它抓到什么。

## 跑一遍（应该全绿）

```bash
pip install markdown          # 唯一依赖

cd example/demo-module/04_工具
python3 check_consistency.py
```

预期输出：

```
订单履约监控（示例） · PRD/原型 一致性校验

✅ 规则全部通过，文档一致性校验通过。
```

退出码 `0`。

## 故意改错一个数字（看它抓什么）

打开 `02_需求文档/PRD_订单履约监控_v1.0.md`，把第四节的
「以下 **5** 个维度」改成「以下 **4** 个维度」，保存，**不要重新生成 h5**，再跑一次：

```bash
python3 check_consistency.py
```

预期输出：

```
❌ 发现 2 处不一致：

   [R1-版本同步] .md 已修改但 h5 未重新生成（指纹 b4980a937986 ≠ h5 记录 cf4e8bfd35cb），请运行 build_h5.py
   [R12-数值声明] 声明「以下 4 个维度」= 4，但应为 5（第四节列出的维度数）

结论：未通过（2 处错误）
```

退出码 `1`。

**只改了一个数字，抓出两个问题**：

1. **数值自相矛盾**（R12）—— 文字说 4 个，下面实际列了 5 个。这种错误人眼和 LLM 通读都会顺过去，因为它两段都"读得通"。
2. **派生文档已过期**（R1）—— h5 是给研发看的阅读版，你改了 .md 却没重新生成，研发打开拿到的还是旧内容。

第 2 个才是真正致命的：它不是"写错了"，是"改了但没同步"，而没人会主动去查。

还原改动：

```bash
python3 build_h5.py          # 重新生成 h5
python3 check_consistency.py # 回到全绿
```

## 目录结构

```
demo-module/
├── 02_需求文档/PRD_订单履约监控_v1.0.md        ← 唯一可信源
├── 02_需求文档/PRD_订单履约监控_v1.0_h5.html   ← 由 build_h5.py 生成
├── 03_原型设计/prototype.html                  ← 交互原型
└── 04_工具/
    ├── check_consistency.py
    ├── build_h5.py
    └── consistency_config.json                 ← 本模块配置
```

`04_工具/` 里的两个 .py 是 `scripts/` 的副本——真实项目里从 `scripts/` 复制过去即可。

## 这个示例开了哪些规则

`"enabled_rules": ["R0","R1","R2","R3","R5","R6","R8","R12","R13","R14"]`

没开的 R4（订单类型语义）、R7（精度表述）、R9（章节引用）、R10（字段定义）、R11（门户版本）
需要更特定的 HTML 结构或额外文档，示例里没有，关掉避免误报。

## 两个容易踩的格式坑

写自己的配置和原型时注意：

1. **原型里的剩余时间必须是纯时长，不带空格和前缀。**
   `1小时30分` ✅ ／ `剩余 1 小时 30 分` ❌（解析器要求 `[\d天小时分]+`，有空格或前缀会被跳过，R3 静默不校验）

2. **PRD 里说明"禁用某词"时，不要把这个词原样写出来。**
   写「统一使用「已过期」」✅ ／ 写「禁止使用「已失效」」❌（R13 会把这句话本身判为违规，自指误报）
